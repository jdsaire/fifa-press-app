# Components/

Holds pieces of the app meant to be reused across more than one screen — as opposed to `Pages/`, which holds screens meant to be visited directly at their own web address. This distinction is why the two live in separate folders even though both hold the same kind of file (`.razor`).

- **`AccessCard.razor`** — the headline: what you hold right now. Structurally an `EventCard` variant, with one deliberate difference — no edit toggle, because this data isn't the reader's to change. It keeps accreditation and match access as two visually separate blocks, since the standing credential and access to any one match are genuinely different things.
- **`ChangeRow.razor`** — one entry in the record, disclosed in two layers. Collapsed shows what changed, when it takes effect, and the foreseeable badge where one applies — fully informative on its own, never just a teaser. Opening it (a `<details>`/`<summary>` pair, so it needs no JavaScript at all) reveals why, what to do next, and — when it replaces an earlier entry — the value it replaced, shown alongside rather than hidden. A row you just wrote yourself arrives already open and animates in, rather than sitting in the list indistinguishable from the rows that were already there.
- **`ForeseeableBadge.razor`** — marks an entry that hasn't happened yet, so a condition is never mistaken for a decision already taken. Outlined rather than coloured, because giving it a status colour would imply an outcome the app doesn't know. Its label resolves at render time from the active language rather than being fixed once when the component is created — the fix for one of three places a translated string used to go stale on a language switch.
- **`StaleIndicator.razor`** — how old the information on screen is. Renders *always*, including when the data is seconds old, because an indicator that only appears when something is wrong teaches people to read its absence as "fine" — and absence is what a broken sync looks like too. Its wording — including which of "1 hour" and "3 hours" applies — comes from the per-locale resources rather than a hand-rolled "add an s," because Spanish and Portuguese don't pluralize that way.
- **`AppearanceControl.razor`** — the appearance control on the Settings screen, with three states rather than two: System, Light and Dark. Its predecessor was a strict light/dark toggle, and "system" was a state the app could be in but never one a person could choose and return to. Choosing System clears the stored preference rather than storing a third value, which is exactly what the theme module already meant by storing nothing — so the tri-state needed no new JavaScript at all.
- **`LanguageSelect.razor`** — the EN/ES/PT control, a labelled dropdown on the Settings screen. It was three buttons when it was a persistent sidebar row, on the reasoning that a picker exists to manage a list too long to show and three is not that. That reasoning was not overturned; the control moved. Beside other labelled fields on a screen you visit deliberately, a dropdown is the register of its neighbours. Switching still re-renders the tree in place with no page reload, so it still never signs anyone out.
- **`SignInForm.razor`** — the sign-in experience: the simulation notice, the two-field form, and both demo accounts published on screen with their passwords. It was a page at `/signin` until this run and now has no address of its own, because the screen it belongs on is the record — a person signed out of the record needs the form, and sending them elsewhere to find it made the app answer "where do I sign in" in two places.
- **`RequestAccessForm.razor`** — the request form's fields and validation, extracted so the pattern lives in one place: per-field messages tied to their input for screen readers, and element ids made unique per instance so two forms on a page can't collide.
- **`EventCard.razor`** — the original reusable card, and the pattern the others follow. The match screens reuse it as-is for read-only presentation, opting out of its edit toggle.
- **`Icon.razor`** — a small set of decorative SVG glyphs (date, location and phase on the match surfaces; home, matches, record, help and settings beside the navigation labels), drawn in this repository rather than pulled from a package. Every one is `aria-hidden` and inherits its colour from the text beside it, so it adds a picture without ever taking a word away or needing its own entry in either theme.
- **`LocaleProvider.razor`** — sits at the top of every page (from `Layout/MainLayout.razor`) and cascades the active language as a value every other component below it can read. It also owns the one piece of interop the language needs: applying `document.documentElement.lang` and remembering the choice, for the same reason `AppearanceControl` owns its own persistence.

A component here has no web address of its own and can't be visited directly; that one-line difference is the whole reason `Pages/` and `Components/` are separate folders.
